# Ascend 服务器自适应执行与协作策略

状态：自 2026-08-01 起用于新的服务器任务与未关闭任务；历史任务中的禁止修改、零重试或逐文件固定 SHA 只作为当时的执行记录，不再是项目默认规则。

## 1. 目标优先级

服务器任务的首要目标是回答研究问题、形成可复核证据并安全恢复资源。自动生成的 RED/YELLOW/GREEN 标签、逐文件 SHA 表和“一次失败即停止”都只是辅助机制，不能替代对实际请求、调度、性能和资源证据的判断。

每个任务应区分三层内容：

1. **研究问题与比较边界**：要回答什么，哪些 A/B 差异会影响解释。
2. **实现方案**：运行器、overlay、observer、环境路径、健康检查与工作目录如何实现。服务器 AI 可以根据真实环境调整这一层。
3. **尝试与证据历史**：每次调整前后的代码、命令、原因、结果和资源恢复。失败尝试不覆盖，成功尝试也不抹除前序事实。

## 2. 服务器 AI 的现场授权

服务器 AI 可在任务范围内自行完成以下动作，无需因为旧合同写有 `false` 而停止：

- 修复运行器、observer、task-local overlay、路径解析、代理、换行符、权限和安装布局问题；
- 在独立 Git worktree 或结果目录内创建并应用补丁、包装器和诊断脚本；
- 根据新证据继续执行、重试或改进实现，直到研究问题已回答、同一阻塞重复且没有新信息、资源风险出现或任务与其他会话冲突；
- 对服务器专属代码做验证后，将完整补丁、文件 SHA 和建议提交内容交回开发机；
- 在不会改变研究解释时调整 warmup、健康检查、日志、超时、清理和传输实现。

优先使用任务专属 worktree、临时 overlay 或结果目录，不修改共享 `main` checkout 和已安装包。若真实环境迫使其短暂修改共享位置，必须先保存 diff/哈希，结束时恢复，并在报告中说明。服务器 AI 不直接向远端 `main` 推送；开发机负责审核、合入和发布。

## 3. 科学变量变化不是禁区，但必须显式分支

服务器可以判断原参数、cell 或调度方案无法回答问题，并提出或执行更合适的变体。规则不是“永远冻结”，而是“不悄悄改题”：

- 控制面或兼容性修复未改变 measured 请求和 A/B 含义时，可沿用同一任务并记录 adaptation；
- 参数、请求负载、A/B 差异或指标定义改变时，建立新的 variant/task ID，列出相对上一变体的完整差异；
- 两侧共同变化仍可形成新的 matched 环境；不得把新环境的结果冒充旧环境的严格对照；
- 如果现场证据表明更值得回答另一个问题，服务器应写明理由、预期信息增益和成本，而不是为满足旧标签继续消耗 NPU。

## 4. 自适应执行记录

每个有现场调整的任务至少保存一份 `adaptive_execution_review.json` 或等价记录，包含：

- 基础提交、工作树位置与是否影响共享 checkout；
- attempt 序号、开始/结束时间、命令、退出码和首个有效故障；
- 修改原因、补丁文件、修改前后 SHA-256；
- 是否改变研究问题、measured 请求、A/B 差异、cell 或指标；
- 每次尝试停止/恢复的 NPU 卡集与最终资源状态；
- 采用哪一次尝试形成结果，以及为什么前序尝试仍应保留；
- 服务器建议结论与声明边界。

不再要求把“tracked-clean”本身当成实验有效性的必要条件。更重要的是来源可追溯、共享环境已恢复、执行源码可回收到仓库。自动 grade 也不拥有最终解释权；若标签与结构化证据矛盾，应保留原标签并单独记录证据结论。

## 5. 多会话与资源协作

- 有其他会话使用共享仓库时，新任务优先 `git fetch` 后从 `origin/main` 建独立 worktree，避免 `git pull`、`update-index --skip-worktree` 或 checkout 互相影响。
- 零 NPU 的离线分析、再归档与代码核验可以并行，但不得改写其他任务的结果目录。
- NPU 任务开始前确认所需卡没有被其他任务占用；只停止需要的 keep-alive 卡，任何退出路径都恢复同一卡集。
- 同一阻塞若重复且没有新增诊断信息，应停止消耗 NPU，转为代码修复、离线分析或向开发机交回决策点。

## 6. 结果交付

原始日志与大文件留在服务器。服务器先给出完整的有界清单、字节数、SHA-256、敏感性和推荐渠道；`result_transfer_authorized: true` 只表示可以候选交付。用户选择 `email`、`upload-api` 或 `server-local` 后，才按该完整范围传输。

项目结论优先使用结构化事实，例如请求/批次完成度、调度 token、机制事件、TTFT/E2EL/TPOT/ITL、吞吐、清理和卡恢复。颜色标签可以保留作机器状态，但不得遮蔽或推翻这些事实。
